这篇专门解释参数。号主不理解参数就上架，很容易出现两类问题：用户体验差，或者收益和风险不符合预期。

## 三种模式怎么选

| 模式 | 用户是否能选你的账号 | 系统是否自动调度 | 你主要配置什么 |
| --- | --- | --- | --- |
| 私有模式 | 不能 | 只给你自己调度 | 并发、账号可用性 |
| 公共模式 | 不能，用户只选分组 | 系统自动调度进共享号池 | 账号稳定性、共享校验 |
| 账号模式 | 能，用户在账号广场选择房间 | 房间内调度健康成员账号 | 房间成员、价格、席位、模型、空闲退出 |

新手建议顺序：

```text
私有模式跑通 -> 公共模式校验 -> 账号模式上架
```

## 我的账号里的基础参数

### 并发

并发表示这个账号允许同时处理多少个请求。

并发不是越高越好。过高并发可能导致：

- 上游账号触发风控。
- 请求失败率升高。
- 额度消耗太快。
- 用户看到更多 429 或上游错误。

新手建议保持默认值。等账号稳定后，再根据使用记录逐步调整。

### 优先级

优先级用于调度排序。数字越小，优先级越高。

在用户前台个人账号创建里，优先级通常由系统收口为默认值。你更多需要关注账号是否可调度、共享模式是否正确。

### 账号等级

OpenAI 账号等级影响系统校验和调度。常见有 Free、Plus、Pro、Team。

原则：

- 实际是什么等级，就选什么等级。
- 不确定就按页面提示归入 Free。
- Pro 必须通过账号登录导入，并选择代理 IP。
- Team 只接受实际 Team 账号。

等级选错会导致共享校验失败或账号不可用。

### 过期时间

过期时间用于提醒或限制账号使用。

适合填写：

- 订阅到期日。
- 临时账号到期日。
- 你希望系统停止调度的时间。

如果不确定，可以先不填，但要自己记录账号到期时间。

## 公共共享相关参数

公共模式主要依赖系统校验和站点配置。你需要关注“共享状态”：

| 状态 | 含义 |
| --- | --- |
| 公共已通过 | 账号可进入公共共享号池 |
| 公共待校验 | 系统正在等待或执行校验 |
| 公共已暂停 | 公共共享被暂停，需要看原因 |
| 私有 | 当前不进入公共共享 |

如果看到“上次校验未通过”或“公共共享已暂停”，先处理提示原因，再点击重新校验。

## 账号广场房间模型

账号广场按房间发布。房间包含一套统一的展示与计费策略，也可以包含多个房间账号。

| 层级 | 管理位置 | 主要配置 |
| --- | --- | --- |
| 房间 | 账号广场 | 名称、席位、倍率、单用户并发、小时费、低消、最低余额、模型、保护比例 |
| 成员账号 | 我的账号 | 凭证、代理、单个账号并发、状态、可调度性 |

房间成员必须属于同一号主、同一平台并且账号等级一致。等级为 `unknown` 的账号不能加入。一个账号也不能同时属于两个房间。

### 创建来源

- **选择已有账号**：保留账号 ID、凭证、代理和并发。私有账号会在创建事务中直接切换为平台账号模式；公共号池账号会先安全排空在途请求，再完成切换和建房。
- **登录新账号**：只在账号还未添加时使用 OAuth，同时创建首个账号和房间。

创建完成后，可以在「查看房间账号」中批量加入或移出兼容账号。加入前要先在「我的账号」把候选账号切为对应平台账号模式；移出不会删除账号或修改凭证、代理和状态，最后一个账号移出后房间自动暂停。

## 房间级参数

### 可使用人数 / 席位

席位表示最多允许多少个用户同时激活房间：

```text
2 到 12 人（默认 2）
```

席位越多并不代表越稳定。应同时确认房间内健康账号数和总并发足够。

### 房间总并发与单用户并发

卡片上的“账号并发”是房间内有效成员账号并发之和。单个账号并发仍在「我的账号」中修改，单个账号页面允许的最大值为 50。

房间必须满足：

```text
房间总并发 >= 单用户并发 × 席位
```

单用户并发默认 5，用于防止一个用户耗尽整个房间容量。新增成员账号可以增加房间总并发；成员退出则会减少总并发。

### 账号倍率

倍率是整个房间的请求费用倍率，默认 1：

```text
用户请求费用 = 模型原始费用 × 房间倍率
```

页面可能对明显偏贵的倍率给出风险提示。倍率越高不等于收益越高，还要看房间健康度、模型和用户是否愿意加入。

### 小时费与免小时费低消

小时费默认 0.2。其他用户激活房间席位后按分钟预扣，预约等待不收费。

免小时费低消默认 0，表示关闭。启用后按实际激活时长折算，单个核销窗口最长 1 小时。窗口内请求消费达标，就退回该窗口预扣的小时费。

```text
小时费：0.60/小时
低消：0.30/小时
激活：5 分钟
预扣：0.60 × 5 / 60 = 0.05
达标线：0.30 × 5 / 60 = 0.025
```

### 最低余额准入

默认 1。只有其他用户加入房间时校验，用于减少刚激活就余额不足的情况。号主自用不校验最低余额。

### 模型白名单

白名单至少保留一个模型，并且应确保房间成员都能稳定支持。

| 平台 | 当前默认模型 |
| --- | --- |
| OpenAI | `gpt-5.5`、`gpt-5.4`、`gpt-5.4-mini`、`codex-auto-review` |
| Anthropic | `claude-sonnet-4-6`、`claude-opus-5`、`claude-opus-4-8`、`claude-opus-4-7`、`claude-fable-5`、`claude-opus-4-6`、`claude-haiku-4-5` |

用户请求不在白名单里的模型时不会进入房间。新增成员后也要复核模型兼容性。

### Codex / Claude 保护百分比

5 小时和 7 天保护比例用于限制房间共享可使用的额度窗口，范围 1%–100%。下调比例可以给号主预留额度，但房间也会更早停止调度。

### Codex 官方客户端限制

OpenAI 房间可以限制为 Codex CLI 场景。是否开启应与目标用户和实际模型能力一致。

## 空闲退出、预约与结束原因

用户加入或预约时设置空闲退出，默认 10 分钟，范围 1–10080 分钟。预约项激活后才开始生效。

- 每个账号模式 API Key 最多预约 5 个房间。
- 预约不会仅靠页面等待自动激活；后续 API 请求才会按顺序尝试。
- 预约等待不产生小时费，激活后才按分钟预扣。

常见结束原因：

| 结束原因 | 含义 |
| --- | --- |
| `manual` | 用户主动结束使用 |
| `idle_timeout` | 空闲超时自动退出 |
| `prepay_insufficient` | 余额不足以继续预扣小时费 |
| `account_unavailable` | 房间在当时没有可继续使用的健康账号 |

## 号主自用

号主可以用账号模式 Key 绑定自己的房间。请求费用使用站点当前配置的全局自用倍率；页面会显示实时倍率，而不是固定写死的历史示例值。

自用同时具备：

```text
不收小时费
不校验最低余额
不占用共享席位
不产生号主或邀请者收益
```

## 收益分成

公共号池与账号广场房间使用站点当前生效的全局共享分成策略。其他用户产生有效消费后，按策略在号主、符合条件的邀请者和平台之间结算。

- 策略更新只影响后续用量。
- 历史用量保留当时的分成快照。
- 没有符合条件的邀请者时，实际邀请者比例为 0。
- 最终以「使用记录 → 余额流水」为准。

收益怎么产生、去哪看、如何提现见[收益和提现](/docs/owner-income)。

## 新手推荐参数

| 参数 | 建议 |
| --- | --- |
| 席位 | 2 或 3 |
| 单用户并发 | 5，并确保房间总并发满足公式 |
| 账号倍率 | 参考同平台、同等级房间 |
| 小时费 | 0.2 或更低 |
| 免小时费低消 | 不懂先 0 |
| 最低余额 | 低门槛 |
| 模型白名单 | 只放所有成员确认可用的模型 |
| 保护比例 | 先保持默认 |

观察一段时间后，再根据使用率、收益、失败率调整。

## 调参时看哪些数据

不要凭感觉调参。至少看：

1. 账号使用记录。
2. 余额流水里的账号模式收益。
3. 用户是否频繁加入后很快退出。
4. 是否经常满席。
5. 是否经常并发打满。
6. 是否出现大量模型不支持错误。
7. 是否触发上游异常或账号风控。

如果收益低但没人用，可能是价格太高、模型不合适、席位太少或账号不稳定。先改最可能影响用户选择的参数，不要一次改很多项。
