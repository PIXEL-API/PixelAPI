## 用户

用户是平台内的消费主体。用户可以创建 API Key、查看用量、购买订阅或充值余额，也可以在支持的功能中绑定或共享账号。

在使用指南里，用户分成两条教程路径：

| 角色 | 主要目标 |
| --- | --- |
| 普通用户 | 使用 Pixel API 的共享能力，创建 API Key，接入客户端，发送消息并得到回复。 |
| 号主用户 | 把自己的账号添加到平台，自用或共享给别人，并通过共享消耗获得收益。 |

## API Key

API Key 是用户调用网关端点的凭证。它会关联到一个分组，并受状态、额度、过期时间、IP 限制和分组策略影响。

你可以把 API Key 理解成“给客户端使用的密码”。客户端每次请求都要带上它，平台才能知道：

- 是哪个用户发起的请求。
- 应该走哪个分组。
- 应该如何扣费和记录用量。
- 是否触发额度、限速、过期或 IP 限制。

第一次使用时，只需要创建一个绑定共享号池分组的 Key。跑通后再考虑多分组路由、额度限制、速率限制和 IP 限制。

## 分组

分组决定一次请求可以使用哪些上游能力，以及如何计费、限速和调度。常见配置包括：

- 平台类型：OpenAI、Anthropic、Gemini、Antigravity 等。
- 模型价格和倍率。
- RPM/TPM 限制。
- 可用账号池。
- 模型路由和账号模式策略。

Pixel API 常见分组类型：

| 类型 | 说明 |
| --- | --- |
| 系统兜底号池 | 用于保障最终可用性的底牌 |
| 共享号池 | 公共账号按调度策略轮询调用 |
| 账号模式分组 | 用户在账号广场加入房间后，API Key 固定使用当前激活房间 |
| 私有分组 | 个人账号只允许账号本人调用，对其他用户不可见 |

共享分组倍率由站点按账号成本、模型能力和稳定性配置。兜底分组倍率可能更高，适合作为多分组路由的后备。

## Base URL

Base URL 是客户端请求 Pixel API 的入口地址，就是站点域名本身：

```text
https://ai-pixel.online
```

API Key 是“谁在调用”，Base URL 是“调用发到哪里”。两者都要配置正确。

<Callout title="接口后缀要和官方格式对齐">
  接口路径跟在 Base URL 之后，例如 Chat Completions 是 `/v1/chat/completions`，Responses 是 `/v1/responses`。部分客户端的 `API Base` 字段要求填到 `/v1`，以「使用密钥」弹窗给出的配置为准。完整端点列表见 [API 参考](/docs/api)。
</Callout>

## 上游账号

上游账号承载真实模型调用能力，可以是 OAuth 账号、API Key 账号或特定平台凭证。平台通过账号健康状态、额度、并发和调度策略决定是否使用某个账号。

个人用户可将自己的账号托管到平台：

- 私有模式：账号只给自己使用，不进入共享号池。
- 公共模式：账号通过校验后进入共享号池，供其他用户调用并产生收益。
- 账号模式：用户在账号广场选择共享房间；系统在房间内调度同平台、同等级的健康账号。

公共号池与账号广场房间使用站点当前生效的全局共享分成策略。策略可以包含号主、符合条件的邀请者和平台三方比例，只影响后续用量结算；历史用量保留当时的策略快照。具体比例以站点当前配置和余额流水为准。

## 账号广场

账号广场是账号模式的前台市场。号主创建房间，并可把同一号主、同平台、同等级的多个账号加入房间；用户按平台、等级、模型、健康账号、席位、倍率、小时费、最低余额和并发等条件选择房间。

账号广场常见参数：

| 参数 | 含义 |
| --- | --- |
| 账号倍率 | 请求费用倍率 |
| 小时费 | 用户激活占位期间按分钟预扣的费用 |
| 免小时费低消 | 请求消费达到门槛后退回小时费 |
| 最低余额 | 用户加入前必须满足的余额门槛 |
| 健康账号 | 房间内当前健康账号数 / 账号总数 |
| 席位 | 房间允许多少用户同时激活 |
| 账号并发 | 房间内有效成员账号并发之和 |
| 单用户并发 | 单个用户在该房间的并发上限 |
| 模型白名单 | 房间允许调用的模型 |
| 空闲退出 | 连续空闲多久后自动释放席位 |

账号广场完整参数、默认值和上限见[参数说明](/docs/owner-params)，用户侧使用流程见[使用账号广场](/docs/normal-account-mode)。

## 订阅与余额

订阅用于给用户分配周期性额度，余额用于按请求计费或购买商品。开启支付后，用户可自助充值或购买套餐（见[充值与订阅](/docs/wallet/purchase)）。

余额也承载共享账号收益。用户可以将收益留在站内继续消费，也可以按站点规则申请提现。完整的计费与提现规则见[计费与提现](/docs/billing)。

## 用量记录

每次网关请求会记录模型、Token、费用、用户、API Key、分组和上游账号等信息。控制台会基于这些记录展示统计。
