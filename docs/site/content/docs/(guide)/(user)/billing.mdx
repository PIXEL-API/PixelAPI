计费规则散落在各个教程里容易看漏，这一页把它们集中起来。所有金额和比例以站点当前配置为准，本页示例仅帮助理解规则。

## 请求费用怎么算

请求费用由模型实际用量和倍率共同决定：

```text
用户请求费用 = 模型原始费用 × 倍率
```

- 走共享分组时，倍率是该分组配置的分组倍率。
- 走账号广场的账号模式时，倍率是号主设置的账号倍率。
- 走私有分组调用自己的账号时，按私有号池策略计费。

示例：模型原始费用 `0.10`，账号倍率 `1.5x`，则用户请求费用为 `0.15`。

<Callout title="倍率怎么理解">
  分组倍率决定余额消耗和收益结算。例如 `0.03` 倍率表示 0.3 元约等于 10 额度；共享收益和用户消耗按同一倍率理解。
</Callout>

## 小时费与低消

小时费只出现在账号广场的账号模式里，用于防止用户长期占位却几乎不发请求。

| 规则 | 说明 |
| --- | --- |
| 预扣方式 | 不会一次扣满一小时，激活占位期间按分钟预扣 |
| 预约队列 | 用户在预约队列中通常不产生小时费 |
| 免小时费低消 | 号主设置低消门槛后，核销窗口内请求消费达标会退回该窗口预扣的小时费 |
| 关闭低消 | 低消设为 `0` 表示关闭，小时费不退回 |

示例：小时费 `0.60/小时`，激活 5 分钟，预扣 `0.60 × 5 / 60 = 0.05`。若低消为 `0.30/小时`，这 5 分钟的达标线是 `0.30 × 5 / 60 = 0.025`——期间请求费用达到 `0.025` 则小时费退回。

对应的余额流水类型：

- 账号模式小时费预扣
- 账号模式小时费退回
- 账号模式小时费达标退回

## 号主自用规则

号主使用自己上架的账号时，按自用规则处理：

```text
0.005x
不收小时费
不占用共享席位
不产生号主收益
```

公开展示给其他用户的倍率、小时费、低消等参数仍然有效。

## 收益从哪里来

只有其他用户实际使用你的共享账号并产生有效消费后，收益才会按规则结算到余额：

| 来源 | 说明 | 余额流水类型 |
| --- | --- | --- |
| 公共共享号池 | 你的公共账号被共享号池自动调度 | 共享账号收益 |
| 账号广场 | 用户主动加入你的账号模式账号 | 账号模式收益 |
| 邀请分成 | 被邀请用户产生有效共享消费 | 邀请分成收益 |
| 专属分组 | 站点配置了专属分组佣金 | 专属分组佣金 |

两种共享收益的分成是**不同的两套**，均以站点当前配置为准：

| 场景 | 示例分成 |
| --- | --- |
| 公共共享号池 | `85% 用户 / 10% 平台 / 5% 邀请者` |
| 账号广场（账号模式） | `号主 90% / 平台 10%` |

收益是否到账，以「使用记录 → 余额流水」为准。详细的排查方法见[收益和提现](/docs/owner-income)。

## 订阅与余额

订阅用于给用户分配周期性额度，余额用于按请求计费或购买商品。开启支付后，用户可自助充值或购买套餐，操作见[充值与订阅](/docs/wallet/purchase)。

余额也承载共享账号收益：可以留在站内继续消费，也可以按提现规则申请提现。余额、积分、并发、负载额度的区别见[余额与积分](/docs/wallet/balance)。

<Callout>
  充值时金额多出 `0.01` 或 `0.02` 是正常现象——多名用户同时下单相同金额时，系统通过小额差异区分订单，按页面显示金额支付即可到账。
</Callout>

## 提现规则

提现入口在「个人资料 → 余额提现与收款码」。

| 规则 | 说明 |
| --- | --- |
| 最低金额 | `1.00` |
| 小数位 | 最多两位小数 |
| 首次手续费 | 第一次提交提现额外扣 `0.10` |
| 待结算限制 | 同一用户只能保留一笔待结算提现 |
| 收款方式 | 支付宝或微信 |
| 收款码格式 | PNG、JPEG、GIF、WebP |
| 图片大小 | 不超过 1MB |

首次提现的实际扣除是 `提现金额 + 0.10`：例如提现 `1.00`，本次扣除 `1.10`。之后的提现不再收取首次手续费。

提现记录状态：

| 状态 | 含义 |
| --- | --- |
| 待结算 | 已提交，等待处理 |
| 已结算 | 已处理完成 |
| 已取消 | 你取消了申请，金额退回余额 |
| 已拒绝 | 管理员拒绝，按站点规则处理 |

完整操作步骤（上传收款码、提交提现、常见失败原因）见[收益和提现](/docs/owner-income)。
