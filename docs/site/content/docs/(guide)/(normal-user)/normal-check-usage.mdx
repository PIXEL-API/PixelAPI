这一步的目标是：确认刚才那条请求真的被 Pixel API 记录到了。

收到模型回复只说明请求成功返回了；查看使用记录可以进一步确认它用了哪个 API Key、哪个分组、哪个模型，以及花了多少余额。

## 第 1 步：进入使用记录

回到 Pixel API 控制台，点击左侧「使用记录」。

## 第 2 步：刷新并筛选

如果看不到刚才的请求：

1. 点击刷新。
2. 把时间范围扩大到今天或最近 24 小时。
3. 如果有 API Key 筛选，选择刚才测试用的 Key。
4. 如果有状态筛选，先选择全部状态。

## 第 3 步：看请求记录

重点看这些字段：

| 字段 | 你要确认什么 |
| --- | --- |
| 时间 | 是否是刚才测试发生的时间 |
| API Key | 是否是刚创建的 Key |
| 模型 | 是否是你填写的模型 |
| 端点 | 是否类似 `/v1/chat/completions` |
| 状态 | 是否成功 |
| Token | 输入和输出是否有数量 |
| 费用 | 是否产生了合理扣费 |
| 错误信息 | 失败时用来判断原因 |

## 第 4 步：查看余额流水

如果页面有「余额流水」切换，点进去看资金明细。

你可能会看到：

- 请求扣费
- 账号广场小时费预扣
- 小时费退回
- 充值到账
- 兑换码到账
- 邀请或活动收益

普通共享分组第一次测试，通常主要看请求扣费是否出现。

## 使用记录为空代表什么

如果 API 参考或客户端报错，但使用记录完全没有新增记录，通常说明请求没有到 Pixel API。

优先检查：

1. Base URL 是否仍然是官方地址。
2. 客户端是否没有读取新配置。
3. API Key 是否填到了错误 provider。
4. 网络代理或浏览器插件是否拦截。
5. 请求是否发到了另一个站点域名。

如果使用记录里有失败记录，说明请求已经到达 Pixel API，再按状态码和错误信息处理。

## 成功标准

这一页完成后，你应该确认：

1. 使用记录里出现了刚才的请求。
2. API Key、模型、分组或端点符合预期。
3. 如果产生扣费，金额没有明显异常。
4. 你知道失败时应该从使用记录里复制请求 ID 或错误信息给管理员，而不是发完整 API Key。
