Pixel API 里最常见的是两类用户，两条教程路径完全独立，从哪条开始都可以：

## 普通用户一条龙路径

目标：从完全不会 API 开始，最后能在自己的客户端里正常收到模型回复。

<Steps>
  <Step>
    先读 [一条龙跑通总览](/docs/normal-first-message)，知道这组教程最终要拿到账号、余额、分组、API Key、Base URL、模型名和使用记录。
  </Step>
  <Step>
    打开 [开始前准备](/docs/normal-prerequisites)，确认你有 QQ 邮箱、浏览器、注册赠送的 `0.1` 测试额度，以及一个安全保存 API Key 的地方。
  </Step>
  <Step>
    按 [打开站点并确认余额](/docs/normal-login-wallet) 用 QQ 邮箱注册或登录控制台，确认 `0.1` 测试额度到账，并找到「API 密钥」「可用渠道」「使用记录」「充值/订阅」这些入口。
  </Step>
  <Step>
    按 [选择分组和模型](/docs/normal-groups-models) 选一个普通共享分组，并从页面复制当前分组支持的模型名。
  </Step>
  <Step>
    按 [创建 API Key](/docs/normal-create-api-key) 创建第一个 Key。第一次只填名称和分组，先不要开启多分组路由、IP 限制或复杂限额。
  </Step>
  <Step>
    按 [确认 Base URL](/docs/normal-base-url) 分清站点地址、带 `/v1` 的 Base URL 和完整接口地址。
  </Step>
  <Step>
    按 [发送第一条消息](/docs/normal-send-test-message) 在 API 参考页填入 Base URL、API Key、模型和测试消息，点击 `Send`。
  </Step>
  <Step>
    按 [查看使用记录](/docs/normal-check-usage) 确认刚才的请求、模型、分组、Token 和费用都符合预期。
  </Step>
  <Step>
    最后按 [配置客户端](/docs/normal-client-setup) 把同一套 Base URL、API Key 和模型名填进 Codex、Claude Code、Gemini CLI、OpenCode 或通用客户端。
  </Step>
</Steps>

## 号主用户最短路径

目标：把自己的账号添加到平台，完成私有自用或公共共享，并理解如何产生收益。

<Steps>
  <Step>
    先读 [收益路径总览](/docs/owner-start)，理解私有模式、公共模式和账号广场三条路分别能不能产生收益。
  </Step>
  <Step>
    按 [准备账号](/docs/owner-prerequisites) 确认平台、账号等级、凭证类型、代理 IP 和共享风险。
  </Step>
  <Step>
    按 [添加第一个账号](/docs/owner-create-first-account) 进入「我的账号」，先用私有模式新增或导入 1 个账号。
  </Step>
  <Step>
    按 [测试私有自用](/docs/owner-test-private-account) 创建私有分组 Key，先自己发一条测试消息。
  </Step>
  <Step>
    按 [开启公共共享](/docs/owner-public-share) 切公共模式并等待共享校验；如果要用户主动选择你的共享方案，再按 [创建和管理账号广场房间](/docs/owner-account-marketplace) 和 [设置房间定价和限制](/docs/owner-pricing-limits) 操作。
  </Step>
  <Step>
    按 [查看收益流水](/docs/owner-check-income) 确认收益到账，再按 [提现和收款码](/docs/owner-withdrawal-setup) 提交提现。
  </Step>
</Steps>

## 最小验证请求

普通用户和号主自用都可以用 [ChatCompletions 格式](/docs/api/chat-completions) 验证链路。最简单的验证方式：

1. 打开 [ChatCompletions 格式](/docs/api/chat-completions)。
2. 选择 `Chat Completions`。
3. 填入站点地址、API Key、模型和测试消息。
4. 点击 `Send`。
5. 返回区出现 `Pixel API 已连接` 即说明链路已打通。

如果你已经熟悉终端，也可以使用同等的 cURL 请求：

```bash
curl "https://ai-pixel.online/v1/chat/completions" \
  -H "Authorization: Bearer sk-你的密钥" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-5.5",
    "messages": [
      { "role": "user", "content": "你好，请只回复：Pixel API 已连接" }
    ]
  }'
```

## 常见分组

| 分组类型 | 适用场景 | 说明 |
| --- | --- | --- |
| `XXX 共享分组` | 日常模型调用 | 选择你有权限、页面显示可用、余额/订阅满足要求的分组 |
| `XXX 兜底分组` | 主共享分组临时不可用时回落 | 稳定性更强，成本可能更高 |
| 账号模式分组 | 在账号广场选择房间，由房间调度健康账号 | 需要先创建同平台账号模式 API Key |
| 私有分组 | 调用自己的托管账号 | 只对账号本人可见 |

<Callout title="担心号池临时不可用？">
  可以在 API Key 中开启多分组路由，让请求按优先级自动回落到 `XXX 兜底分组`。详见[管理与使用 API Key](/docs/api-keys)。
</Callout>
