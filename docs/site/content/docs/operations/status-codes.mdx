  遇到错误时，先记录请求时间、客户端、API Key、分组、模型和完整报错。仅凭状态码很容易误判。

## 速查表

| 状态 | 常见含义 | 第一步 |
| --- | --- | --- |
| [Reconnecting](#reconnecting) | 分组无可调度账号或本地网络/代理问题 | 切换分组，检查本地代理 |
| [400](#400) | 请求格式、模型名或客户端配置不正确 | 检查请求体和模型映射 |
| [401](#401-unauthorized) | API Key 或 Base URL 错误 | 重新复制 Key，核对 Base URL |
| [403](#403-forbidden) | 余额不足、分组不可用或策略限制 | 先查余额和分组 |
| [404](#404-not-found) | Base URL 或端点路径错误 | 核对 `/v1` 等接口前缀 |
| [413](#413-request-entity-too-large) | 请求体过大 | 减少上下文和附件 |
| [418](#418-im-a-teapot) | 请求被站点策略拦截或上游异常 | 保存信息联系站点支持 |
| [429](#429-too-many-request) | 触发限速或并发限制 | 降低并发或换分组 |
| [502](#502-bad-gateway) | 本地路由配置错误、网络异常或上游短时不可用 | 关闭本地路由模式 |
| [503](#503-service-unavailable) | 分组无可调度账号或模型选错 | 检查分组和模型 |
| [504](#504-gateway-timeout) | 长请求超过网关等待时间 | 保存请求 ID 联系站点支持 |

## Reconnecting

常见原因：

1. 当前分组内没有可调度账号。
2. 本地到站点的网络质量较差。
3. 全局代理或命令行代理没有完全关闭。

处理方式：

1. 优先切换到另一个可用的 `XXX 共享分组` 或 `XXX 兜底分组`。
2. 检查本地代理、终端代理环境变量和客户端代理设置。
3. 完全退出客户端后重新进入。

## 400

通常表示请求格式、模型名或客户端配置不正确。检查请求体、模型映射和客户端是否仍在使用旧配置。

## 401 Unauthorized

常见原因：

- API Key 填写错误。
- Base URL 指向了错误站点。
- Authorization 请求头没有使用 Bearer Token。

处理方式：重新复制 API Key，并确认 Base URL 为 `https://ai-pixel.online` 或站点实际提供的网关地址。

## 403 Forbidden

常见原因：

- 余额不足。
- API Key 绑定的分组不可用。
- IP、额度、过期时间或权限策略不允许。

先检查余额和分组，再查看 API Key 的限制条件。

## 404 Not Found

通常是 Base URL 或端点路径错误。OpenAI 兼容调用应使用 `/v1` 前缀，Anthropic 兼容调用应使用站点文档中给出的入口。

## 413 Request Entity Too Large

请求体过大。减少上下文、缩短附件内容，或确认客户端是否把过大的历史会话一起发送。

## 418 I'm a Teapot

这是请求被站点策略拦截或上游返回异常时可能出现的状态。请保存请求时间、请求 ID、客户端和模型名称，联系站点支持排查。

## 429 Too Many Request

通常是触发限速或并发限制。降低并发、等待一段时间，或切换到更稳定的分组。

## 502 Bad Gateway

常见原因：

1. CC-Switch 本地路由模式或 Codex++ 配置错误。
2. 本地网络、代理或中间服务临时异常。
3. 上游账号短时间不可用。

处理方式：

1. 关闭 CC-Switch 本地路由模式，直接替换配置文件。
2. 关闭系统代理或换一个网络环境测试。
3. 切换到 `XXX 兜底分组` 或另一个可用的 `XXX 共享分组`。

## 503 Service Unavailable

常见原因：

1. 当前分组没有可调度账号，常见于 FREE 或 PRO 共享号池资源紧张时。
2. 客户端选择了错误模型。
3. 使用了不适合检测的模型进行站点可用性测试。

处理方式：

1. 检查 API Key 的分组。
2. 必要时切换到另一个可用的 `XXX 共享分组` 或 `XXX 兜底分组`。
3. 在 CC-Switch 中确认模型代码使用 `gpt-5.5`、`gpt-5.4` 等站点支持的模型。

## 504 Gateway Timeout

通常是长上下文、长输出或上游响应过慢导致网关等待超时。先减少上下文、重新发起较短请求；如果持续出现，保存请求 ID 和时间联系站点支持。

## Codex 常见报错

| 报错 | 含义 | 处理方式 |
| --- | --- | --- |
| `stream disconnected before completion` | 输出达到模型上限或流式连接中断 | 新开会话，减少一次性输出 |
| `Codex ran out of room in the model's context window` | 上下文超过模型窗口 | 新开会话，降低上下文或压缩阈值 |
| `Selected model is at capacity` | 上游模型容量不足 | 稍后重试或切换模型 |

推荐上下文设置：

- `gpt-5.5`：上下文最大值按站点说明设置，压缩阈值建议低于最大窗口。
- `gpt-5.4`：可用于更大上下文任务，仍应保留压缩余量。
